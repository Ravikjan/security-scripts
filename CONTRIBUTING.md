# Участие в проекте

Спасибо, что нашли время помочь. Проект небольшой, поэтому правила простые.

## Что приветствуется

- Новые форматы журналов (nginx, Windows XML, `journalctl -o json`).
- Новые проверки аудита с внятным обоснованием и командой исправления.
- Улучшение распознавания: меньше ложных срабатываний при том же охвате.
- Исправления документации, опечаток, неточностей в примерах.
- Тесты на найденные ошибки.

## Что не принимается

- Внешние зависимости: проект сознательно живёт на стандартной библиотеке
  Python и встроенных модулях PowerShell 7.
- Сетевые вызовы, телеметрия, «облачная» проверка баз.
- Функции, меняющие настройки системы в скрипте аудита: он только читает.
- Реальные IP-адреса, имена хостов и хеши в тестах и примерах.

## Как предложить изменение

1. Создайте issue с описанием задачи (или возьмите существующий).
2. Форк, ветка с осмысленным именем: `feat/nginx-parser`,
   `fix/spray-threshold`, `docs/faq-encoding`.
3. Изменение + тест + обновление документации.
4. Pull request: что сделано, зачем, как проверяли.

## Стиль кода

### Python

- PEP 8, максимальная длина строки — 100 символов.
- Только стандартная библиотека.
- Docstring на русском, идентификаторы на английском.
- Аннотации типов обязательны для публичных функций.
- Ошибки ввода — через `ParseError`/`argparse`, а не `print` + выход.

### PowerShell

- `Set-StrictMode -Version 3.0` и `$ErrorActionPreference = 'Stop'` в каждом
  скрипте.
- Комментарий-помощь в начале файла (`.SYNOPSIS`, `.EXAMPLE`) на русском.
- Одна проверка — один элемент массива в `Get-SecurityCheckDefinition`.
- Проверка обязана возвращать `New-CheckResult` и не бросать исключений
  наружу: их перехватит `Invoke-SecurityCheck`.

### Документация

- Русский язык, обращение на «вы», без канцелярита.
- Каждый новый параметр — в таблицу параметров соответствующего документа.
- Примеры должны запускаться на данных из `samples/`.

## Тесты

```powershell
python -m unittest discover -s tests -t . -v
pwsh -File tests/Test-SecurityBaseline.ps1
```

Требования к тестам:

- Не зависят от сети, прав администратора и конкретной ОС, если это возможно.
- Пишут временные файлы только в `.test-tmp` внутри репозитория.
- Проверяют не только «счастливый путь», но и ошибки: битый заголовок CSV,
  отсутствующий файл, неизвестный формат.

## Коммиты

Сообщение в императиве, первая строка до 72 символов:

```
feat: добавить парсер журнала nginx
fix: не учитывать машинные учётные записи в CSV Windows
docs: описать параметр --window
test: покрыть правило password-spray
```

Тело — опционально: почему изменение нужно и на что влияет.
