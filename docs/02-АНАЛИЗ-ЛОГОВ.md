# Анализатор журналов аутентификации

Скрипт `analyze_logs.py` разбирает журналы аутентификации и находит признаки
брутфорса, распыла паролей и компрометации учётных записей.

## Поддерживаемые форматы

| Формат | Откуда берётся | Пример строки |
|---|---|---|
| `sshd` | `/var/log/auth.log`, `/var/log/secure`, `journalctl -u sshd` | `Oct 26 00:14:01 srv01 sshd[1041]: Failed password for admin from 203.0.113.66 port 51001 ssh2` |
| `win-csv` | Выгрузка журнала безопасности Windows (события 4624/4625) | `2026-10-26T09:11:00,4625,Administrator,203.0.113.77,3,-` |

Формат определяется автоматически (`--format auto`), но его можно указать
явно — это надёжнее для нестандартных журналов.

### Как получить CSV из журнала Windows

```powershell
# Только события входа/выхода, в CSV, за последние сутки
$start = (Get-Date).AddDays(-1)
Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4624, 4625
    StartTime = $start
} |
    Select-Object TimeCreated, Id, @{N='TargetUserName';E={$_.Properties[5].Value}},
        @{N='IpAddress';E={$_.Properties[18].Value}}, @{N='LogonType';E={$_.Properties[8].Value}} |
    Export-Csv -Path events.csv -NoTypeInformation -Encoding utf8
```

Обязательные колонки: время, идентификатор события, пользователь, IP-адрес.
Названия распознаются в распространённых вариантах (`TimeCreated`, `EventID`,
`TargetUserName`, `IpAddress`, `SubjectUserName`, `SourceNetworkAddress`).

## Запуск

```powershell
# Базовый вариант: автоопределение формата, отчёт в консоль
python scripts/log_analyzer/analyze_logs.py samples/auth_sshd.log

# Все журналы из каталога, порог 3 отказа за 5 минут, JSON-отчёт
python scripts/log_analyzer/analyze_logs.py "logs/*.log" --min-failures 3 --window 5m -o report.json

# Выгрузка Windows: не учитывать строки «Invalid user»
python scripts/log_analyzer/analyze_logs.py events.csv --format win-csv --count-invalid-user

# Чтение из stdin (например, из journalctl по SSH)
ssh server "journalctl -u sshd --since today" | python scripts/log_analyzer/analyze_logs.py -
```

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ЖУРНАЛ...` | — | Файлы, шаблоны (`logs/*.log`) или `-` для stdin |
| `--format` | `auto` | `auto`, `sshd`, `win-csv` |
| `--year` | текущий | Год для syslog-строк без года |
| `--min-failures` | `5` | Сколько отказов считать атакой |
| `--window` | `10m` | Окно подсчёта пика: `30s`, `10m`, `2h`, `1d`, `0` — без окна |
| `--spray-min-users` | `5` | Сколько разных учётных записей считать распылом |
| `--count-invalid-user` | выкл. | Учитывать `Invalid user` как отказ |
| `-o`, `--output` | — | Файл отчёта: `.json`, `.csv`, иначе текстовый |
| `--fail-on` | `high` | Порог для кода возврата: `none`, `low`, `medium`, `high`, `critical` |
| `--quiet` | выкл. | Не печатать отчёт в консоль |
| `--no-color` | выкл. | Отключить цвета |

## Правила обнаружения

### `brute-force` — серия отказов с одного адреса

Срабатывает, когда с одного IP накопилось не меньше `--min-failures` отказов.
Важность: `medium` при достижении порога, `high` — от трёх порогов,
`critical` — от десяти.

Правило не дублирует распыл: если отказы равномерно размазаны по
`--spray-min-users` и более учётным записям, находку отдаёт `password-spray`.

### `password-spray` — перебор многих учётных записей

`high` при `--spray-min-users` и более разных учётных записей, `critical` —
при удвоенном пороге. Требуется, чтобы ни на одну запись не приходилось
`--min-failures` отказов: иначе это обычный брутфорс.

### `success-after-failure` — вход после перебора

`critical`. Срабатывает, когда с адреса, где было не меньше `--min-failures`
отказов, затем прошёл успешный вход. Самый тревожный сигнал: пароль мог быть
подобран. Дальше стоит проверить, что делал пользователь после входа.

### `distributed-account-attack` — перебор с нескольких адресов

`high`. Одна учётная запись, не меньше `--min-failures` отказов и не меньше
трёх разных IP-адресов — признак ботнета или прокси-пула.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Находок нет или все ниже порога `--fail-on` |
| `1` | Есть находки уровня `--fail-on` и выше |
| `2` | Ошибка: файл не найден, неизвестный формат, сбой разбора |

Коды возврата позволяют встроить проверку в cron или CI:

```bash
python scripts/log_analyzer/analyze_logs.py /var/log/auth.log -o /var/reports/auth.json --fail-on medium \
  || echo "Обнаружена атака, см. /var/reports/auth.json"
```

```json
{
  "tool": "analyze_logs",
  "version": "0.1.0",

  "stats": {
    "files": ["samples/auth_sshd.log"],
    "format": "sshd",
    "lines_total": 48,
    "lines_skipped": 3,
    "events_total": 45,
    "events_by_action": { "login_failed": 33, "login_success": 3 },
    "duration_sec": 0.002
  },
  "summary": {
    "findings": 4,
    "by_severity": { "low": 0, "medium": 0, "high": 3, "critical": 1 },
    "max_severity": "critical",
    "verdict": "критично: возможна компрометация учётных записей"
  },
  "findings": [
    {
      "rule_id": "brute-force",
      "title": "Брутфорс: серия отказов во входе с одного адреса",
      "severity": "high",
      "details": { "source_ip": "203.0.113.66", "failures": 18 },
      "evidence": ["samples/auth_sshd.log:28: Oct 26 00:14:01 ..."]

```

Поле `evidence` содержит до пяти исходных строк — удобно для отчёта
руководителю или для проверки, что правило не ошиблось.

## Ограничения

- Год в syslog-строках отсутствует: для старых журналов указывайте `--year`.
- Время берётся «как есть», без часовых поясов: сравнивать события из разных
  источников с разными зонами нельзя.
- Строки `Invalid user` по умолчанию не считаются отказами, потому что sshd
  обычно пишет пару «Invalid user» + «Failed password» на одну попытку.
  Если в журнале только `Invalid user` (аутентификация по ключам),
  используйте `--count-invalid-user`.
- Другие форматы (nginx, Windows XML, `journalctl -o json`) не поддерживаются.
  Как добавить свой — см. [05-АРХИТЕКТУРА](05-АРХИТЕКТУРА.md).
