# Аудит базовых настроек безопасности Windows

`scripts/security_audit/Test-SecurityBaseline.ps1` проверяет 18 настроек,
считает оценку защищённости и формирует отчёт. Скрипт **только читает**
систему: ни один параметр не меняется.

## Запуск

```powershell
# Отчёт в консоль
pwsh scripts/security_audit/Test-SecurityBaseline.ps1

# HTML-отчёт для архива или руководителя
pwsh scripts/security_audit/Test-SecurityBaseline.ps1 -OutputPath report.html

# Машиночитаемый отчёт + строгий порог (код 1 при находках high и выше)
pwsh scripts/security_audit/Test-SecurityBaseline.ps1 -OutputPath report.json -FailOn High

# Полноценная проверка — из-под администратора
Start-Process pwsh -Verb RunAs -ArgumentList '-NoExit','-File','.\scripts\security_audit\Test-SecurityBaseline.ps1'
```

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-OutputFormat` | `Console` | `Console`, `Json`, `Csv`, `Html`; без явного указания берётся из расширения `-OutputPath` |
| `-OutputPath` | — | Куда сохранить отчёт; родительские каталоги создаются автоматически |
| `-FailOn` | `High` | Порог важности для кода возврата: `None`, `Low`, `Medium`, `High`, `Critical` |
| `-Skip` | — | Исключить проверки: `-Skip SEC-001,SEC-015` |
| `-Only` | — | Выполнить только указанные: `-Only SEC-006,SEC-008` |
| `-List` | — | Показать список проверок и выйти с кодом 0 |
| `-Quiet` | — | Не печатать отчёт в консоль |
| `-IncludeUnknown` | — | Показать в разделе «Что исправить» причины пропусков и ошибок |
| `-NoColor` | — | Отключить цветной вывод |

## Проверки

| ID | Что проверяется | Важность | Нужен админ |
|---|---|---|---|
| SEC-001 | Брандмауэр Windows включён для всех профилей | High | да |
| SEC-002 | Защита в реальном времени Microsoft Defender | High | да |
| SEC-003 | Базы антивируса не старше 3 дней | Medium | да |
| SEC-004 | Протокол SMBv1 отключён | High | да |
| SEC-005 | Подпись SMB обязательна | Medium | да |
| SEC-006 | UAC (`EnableLUA`) включён | High | нет |
| SEC-007 | Учётная запись «Гость» отключена | Medium | нет |
| SEC-008 | В реестре нет пароля автовхода (`DefaultPassword`) | Critical | нет |
| SEC-009 | RDP либо отключён, либо требует NLA | High | нет |
| SEC-010 | Системный диск защищён BitLocker | High | да |
| SEC-011 | Последнее обновление Windows не старше 30 дней | Medium | да |
| SEC-012 | Минимальная длина пароля ≥ 12 | Medium | нет |
| SEC-013 | Блокировка учётной записи после неудачных входов | Medium | нет |
| SEC-014 | Журнал безопасности включён и ≥ 64 МБ | Low | да |
| SEC-015 | Secure Boot включён | Medium | да |
| SEC-016 | Локальных администраторов не больше трёх | Low | нет |
| SEC-017 | Защита LSA (`RunAsPPL`) включена | Medium | нет |
| SEC-018 | Журналирование блоков сценариев PowerShell | Low | нет |

Проверки, которым нужны права администратора, без них не выполняются и
получают статус `ПРОПУЩЕНО` с причиной «Нужны права администратора».
Итоговая строка отчёта показывает, сколько проверок можно добавить, запустив
скрипт от администратора.

## Статусы

| Статус | Значение |
|---|---|
| `ПРОЙДЕНО` | Настройка соответствует рекомендации |
| `НАРУШЕНО` | Настройка небезопасна; в отчёте есть команда исправления |
| `ВНИМАНИЕ` | Не критично, но лучше исправить (например, устаревшие базы) |
| `ПРОПУЩЕНО` | Проверка не выполнялась: нет прав или компонента |
| `ОШИБКА` | Проверка упала: неожиданное исключение, доступ запрещён |

## Оценка защищённости

Оценка 0–100 считается по выполненным проверкам с весами:
`Critical` — 10, `High` — 5, `Medium` — 3, `Low` — 1.

- `ПРОЙДЕНО` даёт полный вес, `ВНИМАНИЕ` — половину, `НАРУШЕНО` — ноль.
- `ПРОПУЩЕНО` и `ОШИБКА` в расчёт не входят.

Вердикт: 90+ — «отлично», 75+ — «хорошо», 50+ — «удовлетворительно»,
ниже — «плохо».

Из-за исключения пропущенных проверок оценка не завышается: если проверить
удалось только три настройки, оценка описывает именно их, а не всю систему.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Нарушений уровня `-FailOn` и выше нет |
| `1` | Есть нарушение уровня `-FailOn` и выше |
| `2` | Скрипт не смог выполнить работу: неверные параметры, не удалось записать отчёт |

Пример использования в CI или в задаче планировщика:

```powershell
pwsh scripts/security_audit/Test-SecurityBaseline.ps1 -OutputPath C:\Reports\baseline.json -FailOn High -Quiet
if ($LASTEXITCODE -eq 1) {
    Write-EventLog -LogName Application -Source 'SecurityBaseline' -EventId 100 -EntryType Warning `
        -Message 'Базовая проверка безопасности выявила нарушения уровня High и выше'
}
```

## Форматы отчётов

### JSON

```json
{
  "tool": "Test-SecurityBaseline",
  "version": "0.1.0",
  "generated_at": "2026-10-26T01:15:00",
  "computer": "SRV01",
  "user": "admin",
  "is_administrator": true,
  "fail_on": "High",
  "summary": { "total": 18, "pass": 14, "fail": 2, "warn": 1, "skip": 1, "error": 0,
               "score": 88, "verdict": "хорошо" },
  "checks": [
    { "Id": "SEC-001", "Title": "Брандмауэр включён для всех профилей",
      "Severity": "High", "Status": "Pass", "Detail": "Включены профили: Domain, Private, Public",
      "Fix": "Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True" }
  ]
}
```

### HTML

Автономный файл: стили встроены, внешних ресурсов нет — можно отправить
почтой или положить в архив. В шапке карточки с оценкой и счётчиками, ниже
таблица всех проверок с командами исправления.

### CSV

Колонки: `Id, Title, Category, Severity, Status, RequiresAdministrator, Detail, Fix`.
Удобно грузить в Excel или в базу для отслеживания динамики.

## Ограничения

- Это проверка **базового** набора настроек, а не аудит на соответствие
  CIS Benchmark или ISO 27001: покрытие сознательно небольшое.
- Часть настроек читается из реестра: групповая политика может переопределять
  их, но в отчёте будет фактическое значение реестра на момент запуска.
- Парольная политика читается из вывода `net accounts`. На нестандартной
  локали строка может не распознаться — тогда проверка вернёт `ВНИМАНИЕ`
  с пояснением, а не ложное «нарушено».
- Список локальных администраторов и гостевая запись определяются по
  SID (`S-1-5-32-544`, `*-501`), поэтому локализация имён не мешает.
- Скрипт не проверяет подозрительные процессы, автозапуск и сетевые
  подключения — это задачи другого класса.

## Как расширить

Каждая проверка — элемент массива в `Get-SecurityCheckDefinition`: метаданные
(`Id`, `Title`, `Severity`, `RequiresAdministrator`, `Fix`) и сценарий `Check`,
возвращающий `New-CheckResult`. Подробная инструкция —
в [05-АРХИТЕКТУРА](05-АРХИТЕКТУРА.md).
