# Архитектура и расширение

## Общая схема

```
                    ┌─────────────────────────────────────────────┐
   журнал sshd  ───▶│ parsers.py: строки → LogEvent                │
   CSV Windows  ───▶│ (формат определяется автоматически)          │
                    └──────────────────┬──────────────────────────┘
                                       ▼
                    ┌─────────────────────────────────────────────┐
                    │ detectors.py: правила поверх событий         │
                    │ brute-force, password-spray,                 │
                    │ success-after-failure, distributed-account   │
                    └──────────────────┬──────────────────────────┘
                                       ▼
                    ┌─────────────────────────────────────────────┐
                    │ report.py: консоль, JSON, CSV                │
                    └─────────────────────────────────────────────┘
```

Скрипты аудита и извлечения индикаторов устроены проще: один файл, функции
верхнего уровня, тесты импортируют его как модуль.

## Структура кода

```
scripts/log_analyzer/
├── analyze_logs.py          точка входа: разбирает аргументы, вызывает cli.main
└── loganalyzer/
    ├── __init__.py          версия пакета
    ├── models.py            LogEvent, Finding, Action, важности
    ├── parsers.py           SshdParser, WindowsCsvParser, parse_timestamp
    ├── detectors.py         Thresholds, detect() и четыре правила
    ├── report.py            AnalysisResult, консоль/JSON/CSV
    └── cli.py               argparse, glob, коды возврата
```

`scripts/ioc_extractor/extract_iocs.py` и
`scripts/security_audit/Test-SecurityBaseline.ps1` — самодостаточные файлы.

## Поток данных анализатора

1. `cli.run` раскрывает шаблоны файлов и читает каждый с подбором кодировки
   (`utf-8-sig` → `cp1251` → `latin-1`).
2. `get_parser` определяет формат по содержимому, если он не задан.
3. Парсер возвращает список `LogEvent`: тип события, время, IP, пользователь,
   исходная строка и её номер.
4. `detect` группирует события по IP и учётным записям и применяет пороги.
5. Отчёт формируется один раз и используется и для консоли, и для файла.

## Как добавить формат журнала

Нужны два шага: класс-парсер и запись в реестре.

```python
# loganalyzer/parsers.py

class NginxAuthParser(BaseParser):
    """Пример: журнал HTTP-аутентификации."""

    name = "nginx"

    _PATTERN = re.compile(
        r'^(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] "\w+ \S+ \S+" (?P<status>\d{3})'
    )

    def parse_text(self, text: str, source: str = "<stdin>") -> list[LogEvent]:
        events = []
        for line_no, line in enumerate(text.splitlines(), start=1):
            match = self._PATTERN.search(line)
            if match is None:
                continue
            status = int(match.group("status"))
            if status == 401:          # отказ в аутентификации
                action = Action.LOGIN_FAILED
            elif status == 200:
                action = Action.LOGIN_SUCCESS
            else:
                continue
            events.append(LogEvent(
                action=action,
                timestamp=parse_timestamp(line, self.default_year),
                source_ip=match.group("ip"),
                username=None,
                source=source,
                line_no=line_no,
                raw=line.strip(),
            ))
        return events


PARSERS = {
    "sshd": SshdParser,
    "win-csv": WindowsCsvParser,
    "nginx": NginxAuthParser,      # ← новый формат
}
```

Затем добавьте `"nginx"` в `SUPPORTED_FORMATS`, расширьте `detect_format`
и `--format` в `cli.py` (поле `choices`). Не забудьте тест: положите образец
в `samples/` и проверьте, что парсер возвращает ожидаемые события.

## Как добавить правило

Правило — функция, принимающая отказы (или все события) и пороги,
возвращающая список `Finding`:

```python
def _night_logins(events: list[LogEvent], thresholds: Thresholds) -> list[Finding]:
    findings = []
    for event in events:
        if event.action is not Action.LOGIN_SUCCESS or event.timestamp is None:
            continue
        if 1 <= event.timestamp.hour < 5:
            findings.append(Finding(
                rule_id="night-login",
                title="Вход в нерабочее время",
                severity="low",
                summary=f"Вход {event.username} в {event.timestamp:%H:%M}",
                details={"username": event.username, "time": event.timestamp.isoformat()},
                evidence=[event.describe()],
            ))
    return findings
```

Подключите её в `detect` и добавьте тест. Правила не должны зависеть друг от
друга и не должны обращаться к файлам.

## Как добавить проверку аудита

В `Test-SecurityBaseline.ps1` найдите `Get-SecurityCheckDefinition` и добавьте
элемент массива:

```powershell
[pscustomobject]@{
    Id                    = 'SEC-019'
    Title                 = 'Запрещён запуск скриптов из временных каталогов'
    Category              = 'Защита процессов'
    Severity              = 'Medium'
    RequiresAdministrator = $false
    Fix                   = 'Настроить AppLocker или политику ограниченного языка'
    Check                 = {
        $value = Get-RegistryValue -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\SRPV2' -Name 'Enabled'
        if ($null -ne $value -and [int]$value -eq 1) {
            return New-CheckResult -Status Pass -Detail 'Политика включена'
        }
        return New-CheckResult -Status Warn -Detail 'Политика не настроена'
    }
}
```

Требования к проверке:

- **Никогда не менять систему** — только чтение.
- Всегда возвращать `New-CheckResult`; исключения перехватит `Invoke-SecurityCheck`.
- `RequiresAdministrator = $true`, если командлет без прав администратора
  гарантированно падает: тогда проверка честно попадёт в «пропущено».
- Указывать `Fix` с командой исправления или точным путём в интерфейсе.
- Добавить проверку в таблицу `docs/03-АУДИТ-БЕЗОПАСНОСТИ.md`.

## Соглашения

- Python — PEP 8, длина строки 100, только стандартная библиотека.
- PowerShell — `Set-StrictMode -Version 3.0`, `$ErrorActionPreference = 'Stop'`,
  комментарии и сообщения на русском, идентификаторы на английском.
- Тесты: `unittest` для Python, обычные ассерты для PowerShell (Pester не нужен).
- Новое поведение без теста не принимается.

## Тестовые данные

`samples/` содержит синтетику: диапазоны `192.0.2.0/24`, `198.51.100.0/24`,
`203.0.113.0/24` и домены `.example`/`.test`. Никаких реальных адресов,
имён и хешей — это важно и для безопасности, и для лицензионной чистоты.
