# Извлечение индикаторов компрометации

`scripts/ioc_extractor/extract_iocs.py` находит в тексте индикаторы
компрометации (IOC) и готовит их к передаче или публикации.

## Что извлекается

| Тип | Ключ в отчёте | Пример |
|---|---|---|
| IPv4 | `ipv4` | `203.0.113.200` |
| IPv6 | `ipv6` | `2001:db8::42` |
| Домены | `domain` | `evil-c2.example` |
| URL | `url` | `https://evil-c2.example/pay?user=1` |
| MD5 | `md5` | `d41d8cd98f00b204e9800998ecf8427e` |
| SHA1 | `sha1` | `da39a3ee5e6b4b0d3255bfef95601890afd80709` |
| SHA256 | `sha256` | `e3b0c442…b855` |
| Почта | `email` | `attacker@evil-c2.example` |

Адреса проверяются библиотекой `ipaddress`: `999.1.2.3` и `1.2.3` индикаторами
не считаются. Хеши распознаются по длине (32/40/64 шестнадцатеричных символа)
и не «вырезаются» из более длинных строк.

## Запуск

```powershell
# Все типы, отчёт в консоль
python scripts/ioc_extractor/extract_iocs.py samples/threat_report.txt

# Безопасный для публикации вид: 203[.]0[.]113[.]200, hxxps://
python scripts/ioc_extractor/extract_iocs.py report.txt --defang

# Только сетевые индикаторы, без приватных адресов, в JSON
python scripts/ioc_extractor/extract_iocs.py report.txt --types ipv4,ipv6,domain --exclude-private -o iocs.json

# Восстановить индикаторы, которые в отчёте уже обфусцированы
python scripts/ioc_extractor/extract_iocs.py report.txt --refang-input

# Проверить несколько файлов и упасть с кодом 1, если что-то найдено
python scripts/ioc_extractor/extract_iocs.py "reports/*.txt" --fail-on-ioc
```

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ФАЙЛ...` | — | Файлы, шаблоны (`reports/*.txt`) или `-` для stdin |
| `--types` | все | Список через запятую: `ipv4,ipv6,domain,url,md5,sha1,sha256,email` |
| `--exclude-private` | выкл. | Не включать приватные, петлевые, служебные и документационные адреса |
| `--refang-input` | выкл. | Перед разбором восстановить `1[.]2[.]3[.]4`, `hxxps://`, `[@]` |
| `--defang` | выкл. | Выводить индикаторы в безопасном виде |
| `--allow` | — | Файл исключений: по одному индикатору в строке, `#` — комментарий |
| `-o`, `--output` | — | Файл отчёта: `.json`, `.csv`, иначе текст |
| `--fail-on-ioc` | выкл. | Код возврата 1, если найдены индикаторы |
| `--quiet` | выкл. | Не печатать отчёт в консоль |

## Дефанг и рефанг

**Дефанг** превращает опасные строки в безопасные для публикации:

| Было | Стало |
|---|---|
| `203.0.113.200` | `203[.]0[.]113[.]200` |
| `https://evil-c2.example` | `hxxps://evil-c2[.]example` |
| `attacker@evil-c2.example` | `attacker[@]evil-c2[.]example` |

Это защищает от случайного перехода по ссылке из отчёта и от того, что
почтовый клиент сделает индикатор кликабельным.

**Рефанг** (`--refang-input`) решает обратную задачу: если вы получили отчёт,
где индикаторы уже обезврежены, флаг восстановит их до разбора, и они попадут
в результат.

## Белый список

Файл исключений полезен, чтобы убрать инфраструктурные адреса, которые
встречаются в каждом отчёте:

```
# allow.txt
8.8.8.8
time.windows.com
```

```powershell
python scripts/ioc_extractor/extract_iocs.py report.txt --allow allow.txt
```

Исключения сравниваются без учёта регистра. Строки, начинающиеся с `#`,
пропускаются.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Успех (даже если индикаторы найдены) |
| `1` | Найдены индикаторы и указан `--fail-on-ioc` |
| `2` | Ошибка: файл не найден, неизвестный тип, не удалось записать отчёт |

## Ограничения

- Обфусцированный ввод не распознаётся без `--refang-input`.
- Домены с экзотическими TLD и punycode могут не распознаться: регулярное
  выражение рассчитано на латиницу, цифры и дефис.
- Расширения файлов (`setup.exe`, `report.log`) и версии (`1.2.3`) отсекаются
  по списку распространённых «псевдо-TLD», но полностью шум не устраняется:
  результат — черновик для аналитика, а не окончательный список.
- Приватные и документационные диапазоны (`192.0.2.0/24`, `198.51.100.0/24`,
  `203.0.113.0/24`) библиотека `ipaddress` относит к непубличным, поэтому
  `--exclude-private` уберёт и их — это ожидаемое поведение.
- Архивы, PDF и бинарные файлы не разбираются: подавайте на вход текст.
