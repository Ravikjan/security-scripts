# Установка и первый запуск

## Что нужно

| Компонент | Минимальная версия | Для чего |
|---|---|---|
| Python | 3.9 | `analyze_logs.py`, `extract_iocs.py` |
| PowerShell | 7.0 | `Test-SecurityBaseline.ps1` |

Windows PowerShell 5.1 не поддерживается: скрипт аудита использует
возможности PowerShell 7 (тернарные выражения в строках, `$PSStyle`,
современные параметры командлетов).

## Проверка версий

```powershell
python --version
pwsh --version
```

Ожидаемый вывод:

```
Python 3.12.4
PowerShell 7.4.6
```

## Python на Windows: ловушка Microsoft Store

Свежая Windows 10/11 содержит **заглушку** `python.exe` в
`%LOCALAPPDATA%\Microsoft\WindowsApps`. Она отвечает невнятным `Python` без
версии, а `py` сообщает `No installed Python found!`. Это не настоящий Python.

Признак: команда `python --version` печатает `Python` и ничего больше,
а `python -m pip --version` завершается ошибкой.

Как исправить — любой из вариантов:

```powershell
# Вариант 1: winget
winget install --id Python.Python.3.12 -e

# Вариант 2: официальный установщик
# https://www.python.org/downloads/windows/ — при установке отметить
# «Add python.exe to PATH»
```

После установки **откройте новое окно терминала**: PATH обновляется только
для новых процессов.

Проверка, что установился именно нужный интерпретатор:

```powershell
python -c "import sys; print(sys.executable)"
```

Путь не должен содержать `WindowsApps`.

## PowerShell 7

```powershell
winget install --id Microsoft.PowerShell -e
```

или установщик с https://aka.ms/powershell-release?tag=stable.

Если в системе остался только PowerShell 5.1, запускайте скрипт так:

```powershell
pwsh -File .\scripts\security_audit\Test-SecurityBaseline.ps1
```

## Клонирование репозитория

```powershell
git clone https://github.com/<ваш-логин>/security-scripts.git
cd security-scripts
```

## Первый запуск

```powershell
# Анализатор журналов на учебном примере
python scripts/log_analyzer/analyze_logs.py samples/auth_sshd.log

# Проверка настроек Windows (часть проверок — только от администратора)
pwsh scripts/security_audit/Test-SecurityBaseline.ps1

# Индикаторы компрометации
python scripts/ioc_extractor/extract_iocs.py samples/threat_report.txt
```

## Запуск тестов

```powershell
python -m unittest discover -s tests -t . -v
pwsh -File tests/Test-SecurityBaseline.ps1
```

Тесты пишут временные файлы в каталог `.test-tmp` внутри репозитория
(он в `.gitignore`), поэтому системный `%TEMP%` им не нужен.

## Политика выполнения скриптов (Windows)

Если PowerShell блокирует запуск `.ps1`:

```powershell
# Разрешить локальные скрипты для текущего пользователя
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Обходить политику через `-ExecutionPolicy Bypass` не рекомендуется: лучше
разрешить подписанные и локальные сценарии один раз.

## Кодировка консоли

Скрипты выводят текст в UTF-8. В старых консолях с кодовой страницей 866
кириллица может выглядеть «кракозябрами». Решения:

```powershell
chcp 65001                          # переключить консоль на UTF-8
$env:PYTHONUTF8 = "1"               # заставить Python писать UTF-8
```

PowerShell 7 обычно уже работает в UTF-8, поэтому проблема редка.
